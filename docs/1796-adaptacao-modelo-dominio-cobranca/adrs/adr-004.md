# ADR-004: Tornar o Título Financeiro Obrigatório na Criação de Novos Casos

## Status

Aceito

## Data

2026-08-05

## Contexto

O `POST /api/cases` atual aceita dados financeiros livres e não recebe a origem da obrigação. A tela de contrato também usa parcelas legadas e permite iniciar cobrança para títulos pendentes.

## Decisão

Exigir `financial_title_id` no `POST /api/cases` para novas criações. Campos denormalizados permanecem somente para leitura e compatibilidade com registros legados. A tela de contrato deve consultar o título canônico e enviar seu identificador.

## Alternativas Consideradas

### Alternativa 1: Aceitar payload novo e legado temporariamente

- **Descrição**: Manter dois formatos no mesmo endpoint durante um período.
- **Prós**: Reduz quebra imediata para consumidores desconhecidos.
- **Contras**: Mantém a criação sem origem confiável e prolonga a regra duplicada.
- **Por que foi rejeitada**: O consumidor principal é controlado pelo projeto e pode ser atualizado junto com a API.

### Alternativa 2: Criar uma nova rota e manter a rota atual

- **Descrição**: Adicionar uma rota canônica sem alterar `POST /api/cases`.
- **Prós**: Evita mudança no contrato existente.
- **Contras**: Mantém dois caminhos de criação e permite que o legado continue gerando casos inválidos.
- **Por que foi rejeitada**: Não garante a regra em todos os pontos de entrada.

## Consequências

### Positivas

- Toda nova criação tem uma origem financeira explícita.
- O contrato HTTP fica alinhado ao agregado Caso de Cobrança.
- A UI pode apresentar erros de elegibilidade com base em um título real.

### Negativas

- Consumidores externos não documentados podem receber erro até serem atualizados.
- A tela de contratos precisa migrar da parcela legada para o título canônico.

## Notas de Implementação

Respostas `400`, `404` e `409` devem ter códigos de erro estáveis e mensagens acionáveis. Leituras de registros antigos devem continuar funcionando enquanto `financial_title_id` permanecer nulo para casos sem backfill seguro.
