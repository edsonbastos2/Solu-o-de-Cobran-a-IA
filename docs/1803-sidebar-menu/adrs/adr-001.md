# ADR-001: Sidebar de navegação no padrão shadcn, implementado do zero

## Status

Accepted

## Data

2026-08-08

## Contexto

Os itens de navegação (Dashboard, Casos, Acordos, Contratos, Clientes, Agentes IA, Políticas) estão hoje no `components/header.tsx` como links de topo, e já **não cabem mais no header** — além de configurações, painel admin e seletor de tenant (só super-admin). O usuário pediu um menu Sidebar inspirado no componente shadcn `Sidebar` (`https://ui.shadcn.com/docs/components/radix/sidebar`), mas o projeto **não possui shadcn instalado** (sem `components/ui/`, sem `@radix-ui/*`). Portanto a decisão envolve: (a) layout de navegação lateral persistente, e (b) implementação do componente de forma autônoma, sem introduzir a stack shadcn/Radix.

## Decisão

Adotar um **shell shadcn completo, implementado do zero** (sem instalar Radix/shadcn):

- Componente `Sidebar` colapsável do tipo `icon` no desktop e `offcanvas` (drawer/overlay) no mobile, com `SidebarProvider`/contexto, `SidebarHeader` (marca + seletor de tenant), `SidebarContent`, `SidebarGroup` com seções com labels, `SidebarMenu`/`SidebarMenuItem`/`SidebarMenuButton`/`SidebarMenuSub`, `SidebarFooter` (ação de usuário/sair) e `SidebarTrigger`.
- Navegação **config-driven**: um array tipado com seções, ícones e RBAC (item `admin` só para super-admin); mesma config alimenta desktop e mobile, sem duplicar lógica.
- Deslocar da navegação do header para o sidebar em **todas as páginas** (todas as telas que hoje importam `<Header>`), inclusive admin.
- Marca (logo CobrançaIA) no topo do sidebar; header enxuto com trigger de collapse, nome do usuário, tour guiado e logout.
- Preservar os atributos `data-tour` existentes (`app-logo`, `header-settings`, `agents-nav-desktop/mobile`, `policies-nav-desktop/mobile`, `mobile-menu-trigger`) e o fluxo de tenant `useActiveTenant`.
- Utilizar tailwind-merge + clsx + lucide-react já presentes no projeto; GUI atalho de teclado `cmd/Ctrl+b` e estados acessíveis (ARIA).

## Alternativas Consideradas

### Alternativa 1: Instalar shadcn/ui (Radix)

- **Descrição**: Usar `npx shadcn add sidebar` e a stack Radix.
- **Prós**: Componente pronto, testado e mantido; menos código próprio a manter.
- **Contras**: Introduz dependências novas (Radix primitives) no primeiro momento; aumenta bundle e o custo de manutenção da stack; fora da preferência "implementar do zero" do usuário.
- **Por que foi rejeitado**: o usuário pediu explicitamente que, se não houver shadcn, o componente seja implementado do zero.

### Alternativa 2: Sidebar fixo simples (não colapsável), menu flat, mobile dropdown

- **Prós**: menor esforço de implementação; risco baixo.
- **Contras**: não escala com a lista crescendo; não aproveita o padrão shadcn de colapsar para ícones no desktop e drawer no mobile; duplicação de lógica mobile.
- **Por que foi rejeitado**: o usuário escolheu a Abordagem A ("Shell completo", colapsável, drawer mobile).

## Consequências

### Positivas

- Navegação organizada em seções, colapsável no desktop (ganho de espaço) e drawer natural no mobile.
- Única fonte de verdade da navegação (config tipada) para desktop e mobile.
- Zero dependências novas além das que já estão no projeto.

### Negativas

- Manutenção de um componente de média complexidade implementado manualmente.
- Necessidade de refatorar o `<Header>` em todas as páginas (troca por shell com sidebar + header slim).

### Riscos

- Regressão no tour guiado (`data-tour`) — mitigar preservando os mesmos atributos/ids.
- Perda do estado de layout ao navegar entre páginas — mitigar mantendo o `SidebarProvider` no `app/layout.tsx` (estado global persistente).
- Regressão no multi-tenant (super-admin) — mitigar mantendo `TenantSwitcher` e item admin condicionais.

## Notas de Implementação

- Componentes novos a criar (em `components/`): `sidebar.tsx` (provider + primitivas), `app-sidebar.tsx` (config-driven, usa `useActiveTenant` e ícones lucide), `sidebar-trigger.tsx`, `sidebar-provider.tsx` (ou unificar em um arquivo).
- Reutilizar `hooks/use-mobile.ts` (já existe) para isMobile.
- Config tipada (ex.: `lib/navigation.ts`) com `label`, `href`, `icon`, `section`, `adminOnly?`.
- `header.tsx` passa a renderizar apenas logo/marca (se houver), trigger do drawer mobile, nome do usuário, tour e logout, sem os `navLinks`.
- Alinhar visual ao design system atual: fundo `#111318`, bordas `white/5`, accent `emerald-500`, dark theme.
