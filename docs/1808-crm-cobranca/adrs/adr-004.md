# ADR-004: @dnd-kit para o drag-and-drop do Kanban

## Status

Accepted

## Data

2026-08-25

## Contexto

O board do CRM exige drag-and-drop de cards entre colunas, com alternativa acessível por teclado (requisito do PRD), atualização otimista com rollback e feedback de erro. O projeto não possui hoje nenhuma biblioteca de drag-and-drop (verificado em `package.json`). Stack: React 19, Next.js 15, Tailwind CSS 4.1, `motion` já transpilado.

## Decisão

Adotar **`@dnd-kit/core` + `@dnd-kit/sortable`** para a interação de arrastar do board:

- Suporte maduro a React 19 e a sensores de teclado (`KeyboardSensor`) — cumpre o requisito de acessibilidade sem implementação manual.
- Atualização otimista: o drop dispara `mutate` do SWR com rollback automático em erro (`isOptimistic`/`rollbackOnError`), padrão já usado no projeto.
- Complementado por ação de menu "Mover para etapa..." no card, garantindo que mover caso nunca dependa exclusivamente do mouse.

## Alternativas Consideradas

### Alternativa 1: Drag-and-drop nativo HTML5

- **Prós**: Zero dependências; bundle menor.
- **Contras**: Acessibilidade por teclado e consistência cross-browser exigem implementação manual extensa; API de eventos frágil (drag image, touch).
- **Por que rejeitada**: Custo de implementação e risco de acessibilidade superam o benefício de evitar a dependência.

### Alternativa 2: motion (já no projeto) para DnD customizado

- **Prós**: Sem dependência nova.
- **Contras**: `motion` é biblioteca de animação, não de DnD — seria reconstruir sensores, hit-testing e teclado manualmente.
- **Por que rejeitada**: Ferramenta errada para o problema.

## Consequências

### Positivas

- Acessibilidade por teclado de graça; API declarativa; comunidade ativa.

### Negativas

- Duas dependências novas (~30–40 kB gzip combinadas) — aceitável frente ao escopo da interação.

### Riscos

- Bundle maior → mitigação: import por subpacote (`@dnd-kit/core` e `@dnd-kit/sortable` são tree-shakeáveis) e uso apenas na página do CRM (code splitting automático do App Router).

## Notas de Implementação

- Instalação: `npm install @dnd-kit/core @dnd-kit/sortable @dnd-kit/utilities`.
- O board nunca decide regra de negócio: ao dropar, apenas chama o hook `useCrmBoard().moveCase(caseId, toStage)` — validação de transição para UX usa o domínio compartilhado (`lib/crm/stages.ts`), autorização real permanece no backend.
