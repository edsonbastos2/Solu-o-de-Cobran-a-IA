# ADR-004: Implementação single-file do redesign de login

## Status

Accepted

## Date

2026-08-08

## Contexto

O PRD (docs/1802-redesign-tela-login/prd.md) define um redesign split-screen da tela de login com coluna de branding e formulário completo. O projeto não possui design system de primitivas; formulários são escritos inline (receita dark de inputs copiada). A lógica de auth atual usa `supabase.auth.signInWithPassword` dentro de `app/login/page.tsx` com `useState`/`useEffect`. Flags no MVP: "esqueci minha senha" apenas visual (ADR-003), "lembrar de mim" sem efeito de persistência, rodapé com links placeholder.

## Decision

Implementar o redesign inteiramente em **arquivo único** `app/login/page.tsx`, preservando a lógica de auth existente:
- Reestruturar o JSX para grid `lg:grid-cols-2` (branding à esquerda, form à direita), empilhando em 1 coluna em telas < `lg`.
- Branding: fundo `#0c0d10`, gradiente azul/roxo decorativo + glow emerald, logo CobrançaIA (ícone Bot em bloco emerald), 3 benefícios com ícones lucide, composição ilustrativa CSS, avatares e nota de confiança.
- Form: inputs email/senha com labels, toggle de senha (olho lucide), checkbox "Lembrar de mim" (visual), link "Esqueci minha senha" sem navegação (`aria-disabled`), botão "Entrar" com estado de carregamento.
- Rodapé legal com links placeholder (sem href real) + copyright.
- Conteúdo de branding: textos fixos como constantes dentro do arquivo.
- Lógica de persistência inalterada (`signInWithPassword`); "Lembrar de mim" e "Esqueci minha senha" são apenas visuais no MVP.

## Alternativas Consideradas

### Alternativa 1: Componentes separados (components/login/BrandingPanel.tsx, LoginForm.tsx)

- **Descrição**: Porta o branding e o form para componentes independentes.
- **Prós**: page.tsx fino; reusabilidade e testabilidade isoladas do form.
- **Contras**: Mais arquivos; o projeto `components/` só tem componente de feature; YAGNI — um único lugar usa essa tela.
- **Por que foi rejeitado**: O fluxo de auth e o layout não são reutilizados em outro ponto. Com o padrão atual de forms inline, um arquivo único é suficiente e menos over-engineering.

### Alternativa 2: "Lembrar de mim" com persistência real

- **Descrição**: Alterar opções de `signInWithPassword` para aplicar persistência quando marcado.
- **Prós**: funcional.
- **Contras**: Supabase já persiste cookie; alterar persistência por sessão requer manipulação do SSR handshake e comportamento do middleware, ampliando o escopo do MVP.
- **Por que foi rejeitado**: O usuário escolheu "somente visual" no MVP. Backlog futuro.

## Consequências

### Positivas

- Mudança localizada no único arquivo de auth — baixo risco de regressão.
- Zero dependências novas, zero novas rotas, zero novos components.
- Alinhado com o padrão de forms inline do projeto.

### Negativas

- `page.tsx` cresce (~200 linhas), concentrando a extensão da marca no arquivo.
- Conteúdo de branding duplica no arquivo único.

### Riscos

- Regressão no fluxo de auth — mitigar preservando o `useEffect` de check de sessão e o handler `handleLogin` inalterados.
- Acessibilidade — garantir labels, `aria-label` no toggle e `aria-disabled` no link placeholder.

## Notas de Implementação

- Usar breakpoint `lg` (`lg:grid-cols-2`), esconder parte da branding em mobile (`hidden lg:flex` para elementos não essenciais).
- Ícones lucide: Bot, Handshake, FolderKanban, MessageSquare, ShieldCheck, Eye, EyeOff, LogIn, Lock, Mail, CheckCircle2.
- Gradientes: `from-indigo-500 to-purple-500` decorativo, cores em `bg-gradient-to-br`, glow com `shadow-emerald-500/20`.
